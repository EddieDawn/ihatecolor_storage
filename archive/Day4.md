# Day 4 — 사진 목록 리뷰 반영과 개발 서버 수명 분리

> 작업일: 2026-08-21  
> 프로젝트: 웨딩 스냅 사진작가 포트폴리오 사이트

## 1. 작업 목표

`codex/photos-page` PR의 추가 리뷰를 검토해 사진 목록의 미구현 이동과 페이지네이션 접근성 문제를 정리했다. 함께 드러난 Docker 컨테이너와 Astro 개발 서버의 수명 문제를 수정해, 컨테이너 안에서 개발 서버를 필요할 때만 직접 실행하는 방식으로 변경했다.

## 2. FIELD 워드마크의 빈 랜딩 이동 수정

사진 목록 상단의 `FIELD` 워드마크는 `/`로 이동했지만, 현재 `src/pages/index.astro`는 랜딩 페이지 구현 전의 빈 자리표시자다. 이 때문에 사용자가 워드마크를 선택하면 아무것도 없는 화면이 표시됐다.

기존 `Photographer`, `Contact`, `Instagram` 메뉴가 사용하는 안내 다이얼로그를 재사용해, `FIELD`를 선택해도 랜딩 페이지가 구현 예정이라는 안내를 표시하도록 수정했다. 새로운 화면이나 별도의 상호작용 체계는 추가하지 않았다.

## 3. 페이지네이션 후 사진 목록으로 복귀

기존 페이지네이션 링크는 다음 문서의 맨 위로 이동했다. 사용자는 페이지를 바꿀 때마다 소개 영역과 헤더를 다시 지나야 했고, 키보드 포커스도 사진 목록의 맥락을 이어받지 못했다.

다음과 같이 수정했다.

- 숫자 및 `Previous`/`Next` 링크에 `#journal-title` fragment를 추가했다.
- 사진 목록 제목인 `Journal`을 스크립트로 포커스할 수 있도록 `tabindex="-1"`을 지정했다.
- fragment가 있는 페이지로 이동하면 목록 제목으로 스크롤한 뒤 포커스를 이동한다.
- 문서 메타데이터의 `prev`/`next` 링크에는 화면 이동용 fragment를 넣지 않았다.

이제 페이지 이동 후 사진 그리드의 시작점으로 바로 복귀하며, 키보드와 보조 기술 사용자에게도 현재 위치가 전달된다.

## 4. JOURNAL 포커스 박스 수정

페이지 이동 후 `JOURNAL` 주변에 가로로 긴 검정 사각형이 나타나는 현상을 확인했다. 이는 새로 생긴 요소가 아니라 기존 전역 `:focus-visible` 윤곽선이었다.

`Journal` 제목이 CSS Grid 셀의 전체 너비로 늘어나면서 포커스 윤곽선도 그 너비만큼 표시된 것이 원인이었다. 접근성에 필요한 윤곽선을 제거하지 않고 제목에 `justify-self: start`를 적용해 포커스 영역을 실제 글자 너비로 제한했다.

## 5. Docker 컨테이너와 개발 서버 수명 분리

기존 `compose.yaml`은 컨테이너의 대표 명령으로 `pnpm dev`를 실행했다. Docker 컨테이너는 대표 프로세스가 종료되면 함께 종료되므로, `astro dev stop`이나 `Ctrl+C`로 개발 서버를 끄면 컨테이너도 종료됐다.

원하는 개발 방식은 다음과 같다.

1. Docker 컨테이너를 실행한다.
2. Dev Container에 접속한다.
3. 필요할 때 `pnpm run dev`로 Astro 서버를 실행한다.
4. 필요하지 않을 때 `Ctrl+C`로 서버만 종료한다.
5. 서버가 꺼져 있어도 컨테이너는 유지한다.

이를 위해 `compose.yaml`을 다음과 같이 변경했다.

- 자동 의존성 설치 및 `pnpm dev` 실행 명령을 제거했다.
- 컨테이너 대표 명령을 `sleep infinity`로 변경했다.
- Astro 서버가 항상 실행 중이라고 가정하던 HTTP healthcheck를 제거했다.
- 기존 소스 bind mount, `node_modules`, pnpm 저장소와 포트 연결은 유지했다.

healthcheck를 제거했으므로 Docker는 더 이상 Astro 서버의 HTTP 상태를 자동으로 `healthy` 또는 `unhealthy`로 표시하지 않는다. 이는 서버를 의도적으로 꺼둘 수 있게 한 현재 방식에 따른 trade-off다.

## 6. 컨테이너 외부 접속 오류 수정

수명 분리 후 `pnpm run dev`를 실행하면 Astro가 컨테이너 내부의 `localhost`에만 바인딩됐다. 브라우저에서 `localhost:4321`로 접근할 때 Docker의 포트 연결이 Astro까지 도달하지 못해 `ERR_EMPTY_RESPONSE`가 발생했다.

`astro.config.mjs`에 다음 설정을 추가했다.

```js
server: {
  host: true,
},
```

이제 `pnpm run dev`만 실행해도 Astro가 컨테이너 외부 연결을 받고, 호스트 브라우저에서 `http://localhost:4321`로 접근할 수 있다.

현재 실행 방법:

```sh
docker compose up -d
pnpm run dev
```

개발 서버만 종료할 때는 서버가 실행 중인 터미널에서 `Ctrl+C`를 누른다. 컨테이너 자체를 종료할 때는 호스트에서 `docker compose down`을 실행한다.

## 7. 루트 경로의 백지 화면 확인

접속 문제를 수정한 뒤 `/`에서 표시된 백지 화면은 서버 오류가 아니었다.

- `/`: HTTP 200이지만 응답 본문이 비어 있음
- `/photos/`: HTTP 200이며 사진 목록 마크업을 정상 반환함

현재 `src/pages/index.astro`는 Prototype C 기반 랜딩 페이지가 구현되기 전의 빈 자리표시자다. 따라서 사진 목록 미리보기 주소는 `http://localhost:4321/photos/`다.

## 8. Git 브랜치 정리

로컬 `codex/photos-page`에는 두 개의 작업 커밋이 있고 원격 브랜치에는 GitHub에서 수정된 `AGENTS.md` 커밋이 있어 브랜치가 서로 갈라진 상태가 발생했다.

작업 파일이 겹치지 않아 원격 변경 위로 로컬 커밋을 rebase한 뒤 push했다. 현재 로컬 `codex/photos-page`와 `origin/codex/photos-page`는 같은 커밋을 가리킨다.

오늘 반영된 커밋:

- `746bcdc` — FIELD의 미구현 랜딩 이동 안내
- `3b713c4` — 페이지네이션 포커스 및 Docker 개발 서버 수명 분리
