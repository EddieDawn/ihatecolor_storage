# Wedding Snap Portfolio Design System

> 상태: **Approved / Canonical v1.0**  
> 승인일: 2026-08-14  
> 현재 검증 대상: 데스크톱 1440×900  
> 모바일 디자인: 별도 승인 전까지 미정

## 1. 문서의 목적과 우선순위

이 문서는 웨딩 스냅 사진작가 포트폴리오의 시각적 일관성을 장기적으로 보존하기 위한 기준이다. 이후 구현 과정에서 컨텍스트가 바뀌더라도 색상, 타이포그래피, 여백, 이미지 처리와 움직임이 임의로 변하지 않도록 한다.

시각적 기준 파일은 다음과 같다.

- 랜딩 페이지: [`prototype-c/`](../prototype-c/index.html)
- 사진 목록 페이지: [`prototype-b/`](../prototype-b/index.html)

문서와 프로토타입이 충돌할 경우 이 문서가 우선한다. 다만 이 문서에 없는 시각적 세부 사항은 위 프로토타입의 실제 렌더링을 참고한다.

### 변경 원칙

1. 디자인 변경 요청을 받으면 해당 변경이 일회성 예외인지 전역 규칙 변경인지 먼저 확인한다.
2. 이 문서를 수정하기 전에 사용자 승인을 받는다.
3. 전역 변경은 이 문서에 먼저 반영하고 코드에 적용한다.
4. 변경 후 하단 변경 이력에 날짜, 대상, 이유를 기록한다.
5. 승인 없이 기존 값을 비슷해 보이는 값으로 교체하거나 프레임워크 기본값으로 대체하지 않는다.

## 2. 사이트 구조

### 2.1 랜딩 페이지

- 프로토타입 C의 Editorial Hybrid 구성을 사용한다.
- 첫 화면은 화면 높이를 채우는 대표 사진과 텍스트로 구성한다.
- 대표 사진은 컬러로 표시하고 느린 진입 애니메이션을 사용한다.
- 랜딩 본문은 12열 그리드 기반의 비대칭 사진 에세이로 구성한다.
- 사진 크기, 상하 간격, 좌우 배치를 의도적으로 다르게 사용한다.
- 모든 사진을 동일한 카드 비율로 강제하지 않는다.
- 메인 메뉴의 `Photos` 또는 최종 승인된 동등한 메뉴가 사진 목록 페이지로 이동한다.

### 2.2 사진 목록 페이지

- 프로토타입 B의 Monochrome Journal 구성을 사용한다.
- 데스크톱에서 정확히 3열 카드 그리드를 사용한다.
- 기본 이미지는 흑백이고 마우스 호버 또는 키보드 포커스 시 컬러로 전환한다.
- 카드 아래에 작품명과 장소·연도를 작은 캡션으로 배치한다.
- 목록이 여러 페이지일 때 명시적인 숫자 페이지네이션을 사용한다.
- 무한 스크롤과 자동 추가 로딩은 사용하지 않는다.
- 페이지당 카드 수, URL 형식, 페이지네이션의 정확한 위치는 아직 승인되지 않았다. 구현 전에 사용자에게 확인한다.

### 2.3 사진 상세 보기

- 목록 또는 에세이의 사진을 선택하면 전체 화면에 가까운 라이트박스를 사용할 수 있다.
- 라이트박스는 사진, 작품명, 장소·연도, 현재 순번을 제공한다.
- `Previous`, `Next`, `Close` 조작과 키보드 방향키를 지원한다.
- 상세 보기 안에서 사진을 과도하게 확대하거나 화면을 강제로 크롭하지 않는다. `object-fit: contain`을 우선한다.

## 3. 색상

색상은 순수한 흰색과 검은색 대신 미세하게 따뜻한 종이색과 부드러운 검정을 사용한다. 강한 브랜드 컬러는 현재 시스템에 포함하지 않는다.

### 3.1 공통 핵심 색상

| 토큰 | 값 | 용도 |
|---|---:|---|
| `--ink` | `#11110f` | 주요 텍스트, 선, 어두운 푸터 |
| `--text-secondary` | `#4e4d48` | 본문 보조 텍스트 |
| `--muted` | `#73716b` | 메타데이터, 좌표, 날짜, 섹션 번호 |
| `--line` | `rgba(17, 17, 15, 0.22)` | 구분선과 캡션 상단선 |

### 3.2 랜딩 페이지 팔레트 — Prototype C

```css
:root {
  --ink: #11110f;
  --paper: #f2f0eb;
  --paper-deep: #e9e6df;
  --line: rgba(17, 17, 15, 0.22);
  --muted: #73716b;
  --hero-background: #171917;
  --hero-foreground: #f2f0eb;
}
```

- 기본 배경: `#f2f0eb`
- 저널처럼 구획을 분리하는 보조 배경: `#e9e6df`
- 첫 화면 배경: `#171917`
- 첫 화면 텍스트: `#f2f0eb`
- 대표 사진은 원래의 컬러를 유지한다.

### 3.3 사진 목록 팔레트 — Prototype B

```css
.photos-page {
  --ink: #11110f;
  --paper: #f4f3ef;
  --line: rgba(17, 17, 15, 0.20);
  --muted: #72716c;
}
```

랜딩의 `#f2f0eb`와 목록의 `#f4f3ef` 차이는 두 프로토타입에서 승인된 미세한 차이다. 별도 승인 없이 하나의 값으로 통합하지 않는다.

### 3.4 금지되는 색상 변화

- 순백색 `#ffffff`을 기본 배경으로 사용하지 않는다.
- 순검정 `#000000`을 주요 검정으로 대체하지 않는다.
- 승인되지 않은 포인트 컬러, 그라디언트 또는 네온 색상을 추가하지 않는다.
- 이미지 위에 불투명한 컬러 오버레이를 사용하지 않는다.

## 4. 타이포그래피

### 4.1 승인된 폰트 스택

```css
font-family:
  "Helvetica Neue",
  Helvetica,
  Arial,
  "Pretendard",
  "Apple SD Gothic Neo",
  sans-serif;
```

현재 프로토타입에는 폰트 파일이 내장되어 있지 않다. 따라서 운영체제에 따라 실제 렌더링 폰트가 달라질 수 있다. **픽셀 단위로 동일한 폰트 표현이 필요하다면 웹폰트와 라이선스를 별도로 선정해야 하며, 그 전에는 위 스택을 변경하지 않는다.**

### 4.2 타이포그래피 성격

- 전체적으로 중립적인 산세리프를 사용한다.
- 큰 제목은 얇고 크게, 작은 정보는 대문자와 넓은 자간으로 표현한다.
- 제목에 굵은 볼드체를 사용하지 않는다. 기본 `font-weight`는 `400`, 워드마크는 `500`이다.
- 큰 제목의 자간은 음수로 조여 사진과 비슷한 시각적 밀도를 만든다.
- 작은 캡션은 자간을 넓혀 미술관 라벨과 같은 인상을 만든다.

### 4.3 랜딩 페이지 글자 규칙

| 요소 | 크기 | 행간 | 자간 | 두께 |
|---|---|---|---|---|
| 워드마크 | `23px` | `1` | `0.21em` | `500` |
| 헤더 메뉴·메타 | `9px` | 기본 | `0.075em` | `400` |
| Hero 제목 | `clamp(64px, 6.3vw, 108px)` | `0.87` | `-0.06em` | `400` |
| 에세이 섹션 제목 | `clamp(56px, 6vw, 98px)` | `0.96` | `-0.055em` | `400` |
| 인용문 | `clamp(34px, 3.4vw, 54px)` | `1.16` | `-0.045em` | `400` |
| 중간 문장 | `clamp(39px, 4vw, 64px)` | `1` | `-0.05em` | `400` |
| 섹션 번호·캡션 | `9px` | 약 `1.55` | `0.065em–0.10em` | `400` |
| 한국어 본문 | `11px` | `1.85` | 기본 | `400` |

### 4.4 사진 목록 글자 규칙

| 요소 | 크기 | 행간 | 자간 | 두께 |
|---|---|---|---|---|
| 중앙 워드마크 | `27px` | `1` | `0.22em` | `500` |
| 헤더 메뉴 | `10px` | 기본 | `0.08em` | `400` |
| 소개 제목 | `clamp(48px, 5.35vw, 86px)` | `0.95` | `-0.055em` | `400` |
| 카드 제목·메타 | `10px` | `1.3` | `0.075em` | `400` |
| 필터·페이지네이션 | `10px–12px` | 기본 | `0.04em–0.08em` | `400` |

### 4.5 텍스트 작성 규칙

- 메뉴, 위치, 연도, 섹션 번호, 카드 제목은 영문 대문자 스타일을 기본으로 한다.
- 긴 설명은 한국어 또는 영어를 사용할 수 있지만 한 줄 폭을 짧게 유지한다.
- 사진 위에 긴 제목이나 본문을 겹치지 않는다.
- `Lorem ipsum`보다 실제 포트폴리오에 가까운 짧은 문장을 사용한다.

## 5. 여백과 그리드

여백은 이 디자인의 핵심 요소다. 콘텐츠를 더 많이 노출하기 위해 임의로 압축하지 않는다.

### 5.1 랜딩 페이지 — Prototype C

```css
--side: clamp(58px, 5.2vw, 92px);
```

- 현재 최소 데스크톱 폭: `1100px`
- 우선 검증 화면: `1440×900`
- 헤더 높이: `92px`
- 헤더 열: `1fr auto 1fr`
- Hero 높이: `100vh`, 최소 `760px`
- Hero 열:
  `minmax(150px, 0.7fr) minmax(500px, 2.25fr) minmax(340px, 1.05fr)`
- 에세이·저널 제목 열: `2fr 6fr 2fr`, 열 간격 `40px`
- 에세이 본문: 12열 균등 그리드, 열 간격 `26px`
- 에세이 상하 패딩: 상단 `190px`, 하단 `220px`
- 랜딩 저널 구간 패딩: `170px var(--side) 190px`
- 랜딩 저널 카드 간격: 행 `80px`, 열 `25px`
- About 구간 패딩: `170px var(--side) 190px`
- 푸터 최소 높이: `280px`

### 5.2 랜딩 에세이의 승인된 비대칭 배치

| 사진 | 열 범위 | 상단 오프셋 | 비율 |
|---|---|---:|---:|
| Last Platform | `2 / 8` | `0` | `4 / 5` |
| The Long Way In | `9 / 13` | `310px` | `3 / 4` |
| Before Turning | `8 / 13` | `160px` | `1 / 1` |
| Passing Wall | `1 / 6` | `250px` | `3 / 4` |
| Low Tide Work | `7 / 13` | `240px` | `5 / 6` |
| One Light On | `1 / 6` | `520px` | `3 / 4` |

실제 사진이 교체되면 구도에 맞춰 `object-position`을 조절할 수 있다. 그러나 열 범위, 비율 또는 큰 상하 오프셋을 바꾸는 것은 디자인 시스템 변경으로 취급한다.

### 5.3 사진 목록 페이지 — Prototype B

```css
--side: clamp(32px, 6.25vw, 100px);
```

- 데스크톱 헤더 높이: `132px`
- 헤더 열: `1fr auto 1fr`
- 소개 구간 열: `1fr 2fr 1fr`
- 소개 구간 최소 높이: `440px`
- 소개 구간 패딩: `90px var(--side) 108px`
- 저널 도구 모음 높이: `112px`
- 저널 도구 모음 열: `1fr auto 1fr`
- 카드 그리드: `repeat(3, minmax(0, 1fr))`
- 카드 열 간격: `clamp(18px, 1.9vw, 30px)`
- 카드 행 간격: `74px`
- 카드 이미지 비율: `3 / 4`
- 이미지와 캡션 사이: `12px`
- 캡션 상단 패딩: `15px`
- 캡션 상단선: `1px solid var(--ink)`

### 5.4 여백 금지 사항

- 카드 수를 늘리기 위해 좌우 여백을 축소하지 않는다.
- 랜딩 에세이를 규칙적인 3열 카드로 바꾸지 않는다.
- 사진 목록을 Masonry 레이아웃으로 바꾸지 않는다.
- 카드 사이에 둥근 컨테이너, 배경 박스 또는 그림자를 추가하지 않는다.

## 6. 이미지 처리

### 6.1 공통

- 이미지 모서리는 직각이며 `border-radius`를 사용하지 않는다.
- 카드와 에세이 이미지에는 그림자를 사용하지 않는다.
- 이미지 컨테이너는 `overflow: hidden`을 사용한다.
- 사진은 기본적으로 `object-fit: cover`를 사용하되, 라이트박스에서는 `contain`을 사용한다.
- 인물의 얼굴, 손, 드레스 디테일처럼 중요한 피사체가 잘리면 사진별 `object-position`을 조정한다.
- 사진의 실제 캡션과 대체 텍스트는 별도로 관리한다.

### 6.2 랜딩

- 대표 사진과 에세이 사진은 컬러가 기본이다.
- Hero 대표 사진은 화면 중앙의 가장 넓은 열을 차지한다.
- 사진별 크기와 비율 차이가 스토리 리듬을 만든다.
- 대표 이미지 오른쪽 아래의 작은 순번 표기는 허용한다.

### 6.3 사진 목록

- 데스크톱 기본 상태: `filter: grayscale(1)`
- 호버·포커스 상태: `filter: grayscale(0)`
- 호버 시 확대: `scale(1.024–1.025)`
- 확대는 컨테이너 내부에서만 발생해야 한다.
- 흑백 이미지를 별도 파일로 만들지 않고 CSS 필터를 사용한다.

## 7. 선, 캡션과 장식

- 구분선은 `1px`만 사용한다.
- 기본 구분선은 `rgba(17, 17, 15, 0.22)`이다.
- 사진 캡션 위 선은 `1px solid #11110f`이다.
- 카드 캡션은 왼쪽에 작품명, 오른쪽에 장소와 연도를 둔다.
- 에세이 캡션은 작품명, 장소·연도, 순번의 3열 구조다.
- 아이콘은 최소화하고 텍스트 레이블을 우선한다.
- 둥근 버튼, 배지, 카드 그림자, 유리 효과, 장식용 그라디언트는 사용하지 않는다.

## 8. 모션과 상호작용

### 8.1 Hero 진입

```css
/* 이미지 컨테이너 공개 */
animation: hero-reveal 1.35s cubic-bezier(0.65, 0, 0.2, 1) both;

/* 이미지의 느린 축소 */
animation: hero-image 7s cubic-bezier(0.2, 0.65, 0.2, 1) both;
transform: scale(1.07) -> scale(1);
```

- Hero 이미지는 아래에서 위로 드러나며 한 번만 실행한다.
- 자동 반복, 빠른 전환, 과도한 패럴랙스를 추가하지 않는다.
- 동영상으로 변경하려면 파일 크기와 모바일 대체 이미지를 검토하고 사용자 승인을 받는다.

### 8.2 스크롤 공개

```css
opacity: 0 -> 1;
transform: translateY(30px) -> translateY(0);
transition: opacity 800ms ease,
            transform 900ms cubic-bezier(0.2, 0.7, 0.2, 1);
```

- 한 번 등장한 요소는 다시 숨기지 않는다.
- 모션은 콘텐츠보다 눈에 띄어서는 안 된다.

### 8.3 사진 목록 호버

```css
transition:
  filter 380ms ease,
  transform 700ms cubic-bezier(0.2, 0.7, 0.2, 1);
```

- 흑백에서 컬러로 부드럽게 전환한다.
- 동시에 최대 약 `1.024`까지 천천히 확대한다.
- 카드 자체를 위로 띄우거나 그림자를 추가하지 않는다.

### 8.4 접근성 모션

`prefers-reduced-motion: reduce`에서는 애니메이션과 긴 전환을 사실상 제거한다. 콘텐츠가 애니메이션 완료에 의존해서는 안 된다.

## 9. 페이지네이션 규칙

사진 목록에 페이지네이션을 추가할 때 다음 원칙을 적용한다.

- 숫자 기반의 명시적인 페이지 이동을 사용한다.
- `Previous`와 `Next`를 텍스트로 제공할 수 있다.
- 현재 페이지는 밑줄 또는 색상 농도 차이로 표시한다.
- 채워진 배경, 둥근 pill 버튼, 큰 화살표 아이콘을 사용하지 않는다.
- 페이지네이션은 카드 캡션과 동일한 작은 대문자·넓은 자간 계열을 사용한다.
- 페이지 이동 후 목록의 시작점과 포커스 이동을 고려한다.
- 페이지당 카드 수와 페이지네이션 위치는 구현 전에 사용자 승인을 받는다.

## 10. 접근성과 품질 기준

- 모든 의미 있는 사진에 문맥에 맞는 `alt`를 제공한다.
- 장식용 사진만 `alt=""`를 사용할 수 있다.
- 키보드 포커스는 `1px solid var(--ink)`와 `4px` 오프셋을 기본으로 한다.
- 호버로 제공되는 기능은 키보드 포커스로도 제공한다.
- 제목 구조는 `h1` 다음에 논리적인 `h2`, `h3` 순서를 유지한다.
- 사진의 `width`와 `height` 또는 `aspect-ratio`를 지정해 레이아웃 이동을 줄인다.
- 첫 화면 핵심 이미지만 우선 로딩하고 나머지는 지연 로딩한다.
- 최종 확인은 우선 1440×900에서 수행한다.
- 가로 스크롤, 깨진 이미지, 콘솔 오류가 없어야 한다.

## 11. 구현 가드레일

- 실제 구현에서는 페이지별 토큰 범위를 분리한다. 예: `.landing-page`, `.photos-page`.
- 프레임워크나 CSS 라이브러리를 도입해도 승인된 실제 계산값이 달라져서는 안 된다.
- 라이브러리의 기본 카드, 버튼, 그림자, border-radius 스타일을 그대로 사용하지 않는다.
- 컴포넌트 추출을 이유로 랜딩의 비대칭 배치를 균일화하지 않는다.
- 실제 브랜드명, 메뉴명, 페이지 경로, 사진 수가 결정되지 않은 상태에서 임의로 영구 규칙을 만들지 않는다.
- 프로토타입은 비교 기준이며 실제 제품 코드와 분리해 보존한다.

## 12. 구현 전 확인이 필요한 미결정 사항

다음 항목은 아직 디자인 시스템에 고정되지 않았다.

- 실제 작가명과 워드마크
- 랜딩 Hero에 사용할 실제 웨딩 사진
- 메뉴의 최종 명칭과 URL 경로
- 사진 목록의 페이지당 카드 수
- 페이지네이션의 상단·하단 배치 여부
- 작품 분류 필터 사용 여부
- 한글·영문 병기 방식
- 웹폰트 선택과 라이선스
- 모바일 레이아웃과 모바일에서의 흑백·컬러 정책

이 항목을 구현해야 할 때는 추정으로 확정하지 말고 사용자에게 질문한다.
